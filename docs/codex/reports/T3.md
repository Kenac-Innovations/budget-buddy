## Integration handoff (T8)

1. **T1:** import `sessionStore` or `getSessionStore()` from `@/lib/session`. Both reach one process-wide store. Import `getOrCreate` (also exported as `getOrCreateSession`) from `@/lib/session/cookie`. Call it after validating a real user reply and before streaming, then persist provider messages and the reducer-generated plan through `appendTurn`. Handle `PlanVersionConflict` by reloading rather than replacing newer user decisions. Preserve provider user/assistant messages in their `role`/`content` shape (Chat Completions strings and Responses text blocks are supported).
2. **T2:** resume with `GET /api/plan` on load. A 401 means no resumable session; keep the static greeting. A successful response is `{plan, messages: Array<{role:"user"|"assistant", content:string}>, saved:boolean}`. Replace the initial greeting with “Welcome back.” plus history when messages exist. Refetch on an operation's 409. Use `saved` for “Not saved yet”/“Saved”.
3. **T2:** mount `<SaveForm onSaved={(result) => ...} />` inside `WrapUpCard`, only at wrap-up. Named and default exports are available from `@/components/advisor/save-form`; callback type is `SaveFormResult`, containing `{saved:true, emailed:boolean, returnUrl:string}`. Set header state when it fires. Consume `?notice=link-expired` as “That link has expired.” and `?notice=resume-unavailable` as “We couldn't open your plan. Try the link again in a moment.” These notices belong on T2's page, outside T3 ownership.
4. **T5:** export `buildWorkbook` from `src/lib/export/workbook.ts` and provide `/api/export/xlsx`. Email feature-detects the literal import and passes `(plan, {organisation, role})`; it expects `Promise<Buffer>`. Until then, email includes the export URL and tells the user to open the return link first to establish the download cookie. The download link on the save form likewise becomes live after T5 merges.
5. **T6:** apply its proxy/helper limits to `/api/session/save` and `/r/*`. No T6 helper existed in this checkout, so T3 does not duplicate the limiter. Apply the platform's body-size/CSRF controls. Keep private return tokens out of access-log paths. The expiry guard refuses inactive unsaved sessions after 30 days; physical deletion is T6's retention job. Memory mode is process-local demo/test storage and does not survive restarts or span replicas.
6. **Deletion:** the frozen `SessionStore` has no delete method. T3 has not invented a deletion endpoint or changed that contract. T6/T8 must implement the privacy deletion integration with an agreed store extension or separate database adapter.
7. **Deployment:** apply the migration against Postgres and run a real transactional/round-trip test. Set `APP_URL` to the public URL; requests' Host headers never determine emailed links. Configure `SMTP_HOST`, `SMTP_PORT` (default 587; 465 uses implicit TLS), `SMTP_USER`, `SMTP_PASS`, and an email-shaped `MAIL_FROM`. Credentials are optional only for an unauthenticated relay; user/pass must be provided together. Validate real mailbox delivery and Excel attachment after T5. No T3 model client or model ID was introduced; the advisor's `OPENAI_MODEL` configuration stays with T1.

## Manual test script after integration

3. Leave SMTP unset, save synthetic details, confirm the “Saved” header and return link, copy it, and reopen it in the second browser. Confirm the restored history/plan and no contact details in the resume response. Try an invalid token and confirm the calm notice.
4. Configure a controlled SMTP test mailbox, save again and confirm the emailed success copy. Open the private link, download the workbook, and confirm the attachment/export after T5. Explicitly test contact consent true and false without changing per-line sharing.
5. Stop the server before finishing.
