# T4 · Kenac price list and sourced pricing

An agreed budget line can now look up fitting Kenac catalogue items with dated price-list evidence. Failed constraints exclude an item; unconfirmed fits, expired prices, missing evidence and currency mismatches cannot authorize a price. Attaching a price remains a separate `price_line` operation. The lookup discloses Kenac, offers alternatives and flags competing quotes for public entities.

The CSV importer validates rows, upserts the operator supplier and items in one transaction, deactivates missing SKUs and restores returning SKUs. Rejected SKUs retain their last accepted data; empty or entirely invalid snapshots leave the catalogue unchanged. Decimal strings remain exact. The documented sample is synthetic test data and is never loaded by runtime or demo mode.

## Acceptance criteria

- ✅ **Importing the sample CSV creates the items; re-import is idempotent.** A stateful Prisma transaction double creates five items, re-imports without duplicates or changed source data, deactivates absent items and restores returning ones. Tests also cover rejected-SKU preservation, malformed files and rollback. Postgres is unavailable, so the live database check remains for T8.
- ✅ **An item that fails a constraint is never returned as attachable.** Tests cover `eq`, `gte`, `lte` and `in`, plus a mismatched line unit. Partial fits have `attachable: false`, an unconfirmed label and no attachable price; they never enter `documentedPrices`.
- ✅ **An expired item is returned as unusable with an “Expired · request an updated quote” reason.** Verified directly, including UTC end-of-day validity and separate currency/source-metadata checks.
- ✅ **An attached price shows the “Kenac” badge and “Kenac price list” evidence pill.** A stubbed Responses client runs lookup → `price_line` → persistence through the in-memory session store. Server-rendering the existing `PlanView` verifies both labels and the operator supplier flag. No UI files were changed.
- ✅ **Public-entity flag test.** Both true and false profiles are covered; the model receives `needsCompetingQuotes` from the plan, never from its own input. The tool description requires alternatives and competing quotes when flagged.
- ✅ **Without an imported price list the tool returns empty and nothing breaks.** Tests cover an empty catalogue, absent database configuration and no fitting item. Empty results suggest “Request quotes”; connection failures return a redacted, recoverable result and leave the plan unpriced.
