# T1: Streaming advisor brain

Budget Buddy now serves resumable demo and live advisor turns at `POST /api/advisor/turn`. Live turns use the OpenAI Responses API, propose changes through validated advisor tools, persist each applied op before publishing it, and stream text alongside the living plan. The persona ties spend to business outcomes, keeps technical recommendations conditional and vendor-neutral, and permits vague security requirements. Twelve dated planning topics are explicitly marked **DRAFT, awaiting Kenac review**.

Branch: `codex/T1-advisor-brain`. Local commits only; no remote or push. No frozen contracts changed. No migration or database needed.

## Implementation notes

- `tools/index.ts` advertises the nine advisor ops plus `suggest_wrap_up`. `createToolRegistry(extraTools)` lets T4 add a validated lookup without changing the agent loop. Extensions receive `ToolContext`, including the current plan, an abort signal, user statements and `documentedPrices` for fitting offers.
- JSON schemas come from the frozen zod op variants. Strict mode makes every object property required, represents optional fields as nullable, and prohibits additional properties. Parsing removes optional wire nulls while retaining required nullable quantities. A profile-only update preserves the current planning period and currency despite defaults in the frozen profile schema.
- Price validation uses the frozen reducer, then checks provenance. A model-written reference alone is insufficient. A quote/published price must match amount, currency, reference and dates in one user statement, or be recorded by a trusted lookup. Operator prices require trusted lookup evidence. Missing, expired or malformed evidence leaves the line Unpriced.
- Requests use `store: false`; encrypted reasoning items are retained in session history for stateless tool continuation. Disconnected and timed-out turns append balanced partial history and retain durable ops. Raw provider/storage errors are never published.
- The agent permits eight tool-bearing rounds and then a final text response; a further tool call ends with a retryable limit error. Model/lookup waits are abortable under the 60-second deadline. Persistence completes before op publication and final completion.
- Wrap-up counts accepted objectives/initiatives and uses `planTotals()` directly. Decimal amounts are formatted without conversion to JavaScript numbers. Unpriced accepted lines, pending proposals and missing exchange rates are explicitly reported.
- Demo runs the two frozen fixtures once, then responds safely to pricing and wrap-up requests without repeating the last fixture's proposals. It is a scripted demonstration, not an intelligent substitute for live mode.
- The route runs on Node.js through the existing `cacheComponents` configuration. An explicit `runtime = "nodejs"` export is rejected by this installed Next.js version; its local cache-components guide requires Node.js. `maxDuration = 65` remains supported.
- Shared-file changes are only the existing, preinstalled `openai` dependency entry in `package.json` and its lockfile entries, committed as a separate logical change. No installation or extra dependency was added during implementation.

## Integration handoff (T8)

1. **Wire the shared T3 store before using user-op/save/resume endpoints.** T1 cannot edit T3-owned session files. T1's `getSessionStore()` currently defaults to one in-memory instance (`SESSION_STORE=memory`). After T3 merges, register its shared factory in the advisor route and select it by environment:

   ```ts
   import { getSessionStore as getSharedSessionStore } from "@/lib/session";
   import { registerSessionStore } from "@/lib/advisor/session-store";
   registerSessionStore("shared", getSharedSessionStore);
   // Set SESSION_STORE=shared. All advisor/user-op/save endpoints must use T3's same instance.
   ```

   `registerSessionStore` accepts synchronous or asynchronous factories. Unknown providers fail clearly; they do not silently discard persisted sessions. Confirm T3's environment choice and a database-backed round trip when Postgres is available. The per-session overlap guard is process-local; distributed writes and races with user ops need T3's persistence/concurrency policy.

The model then calls `price_line`, and the loop applies/emits/persists it. A lookup remains necessary in a later turn; model history alone cannot authorize operator evidence.
