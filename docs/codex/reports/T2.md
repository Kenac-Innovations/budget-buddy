## T8 integration notes

- **T1:** UI posts `{message}` to `/api/advisor/turn`, appending `?demo` for demo mode, then validates and consumes the frozen NDJSON protocol. Every operation runs through `applyOp(..., "advisor")`; versions/created IDs are checked and `done.plan` replaces the local copy. The development-only fallback runs only on HTTP 404 in demo mode and is disabled in production. It interleaves unchanged fixture operations with words; after two turns it can emit wrap-up without duplicating the second fixture.
- **T3:** The client already loads `GET /api/plan` with the specified `{plan, messages: [{role: "user" | "assistant", content}], saved}` shape, displays Welcome back plus history, and posts `{op}` to `/api/plan/op`. HTTP 409 refetches the authoritative plan; other failures roll back. Local operation fallback is limited to development demo mode when the endpoint is missing. Check the merged routes and in-memory cookie session together.
- **T3 save form:** Mount T3's `SaveForm` in `WrapUpCard` through `AdvisorScreen`'s `saveForm` prop. Connect `SaveForm.onSaved` to the controlled `saved` prop for immediate header updates. T3's form was deliberately not copied or edited in this branch. `initialPlan` and `initialMessages` props are also available to a client wrapper; ordinary returns use the existing GET loader.
- **T6:** `/privacy` is linked permanently and needs T6's page at integration. Device drafts are validated, have a 30-day expiry checked on access, and use separate demo storage. Align the final data-handling text with the merged session behavior.
- **Fixture flags:** The frozen fixture's installation line has `forgottenCost: true` and shows Spotted. Its standalone firewall line has no proactive flag in the frozen line contract. For the demo's specifically spotted firewall renewal, T1 should propose a proactive initiative and attach the renewal to it. No flags or sources were invented in the UI.
- **Source links:** Sources with HTTP(S) URLs render as dated external links; the fixture's source without a URL remains dated text. The UI does not invent a link.
- **CSS:** The existing Turbopack `*.css` rule remaps module files to plain CSS, leaving CSS-module exports empty. T2 therefore uses namespaced classes and keyframes in its owned `advisor.css`, without changing T6's configuration. Query detection happens after hydration so the greeting remains statically rendered under this Next version's caching rules.
- **Font delivery:** the shared root layout still requests Hanken Grotesk. Next reported that Google Fonts could not be downloaded in this environment, so the captured browser views used its configured fallback. T8 should verify Hanken delivery in the target environment or self-host it in the shared layout.
- No frozen contracts, shared package/schema/layout files or dependencies changed. The explicitly requested sample route is the only source file added outside T2's normal owned directories. No migration was needed.
- Live model, SMTP, export, sharing and cross-device return-link checks remain the relevant workstreams' and T8's end-to-end checks.
