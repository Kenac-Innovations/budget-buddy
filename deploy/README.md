# Kenac deployment

The ArgoCD Application follows the accessible `kenac-gitops/argocd/applications/claimflow.yaml` conventions: labels, finalizer, default project, server-side apply, self-heal, pruning and retry. This repository has no remote; these are reviewable templates, not a deployed service.

Before deploying, fill in the Harbor project and immutable image tag/digest, namespace, database host/user/password/name, public HTTPS domain, ingress class, TLS secret, registry pull credentials if needed, OpenAI credentials and confirmed model ID. Copy only the concrete manifests in `deploy/k8s` into `kenac-gitops/projects/budget-buddy/k8s`. Register the Application separately. Keep the example Secret out of Git; populate it through Kenac's secret management. Confirm network policy for ingress-only app access, Postgres and OpenAI HTTPS egress using cluster-specific selectors.

The inspected cluster has Istio gateways as well as ingress resources. The supplied Ingress is an explicit placeholder; use the approved ingress class or replace with the cluster's Gateway/VirtualService. Keep streaming response buffering disabled, 16 KB upstream body limit, TLS redirect and a turn timeout of at least 120 seconds.

Build with `docker build -t budget-buddy:t6 .`. The image runs as uid/gid 1001, serves Next standalone on 0.0.0.0:3000, validates runtime env and runs `prisma migrate deploy` before starting. It retains the existing node_modules to support Prisma CLI and tsx; this trades size for an offline runtime with no package installs. Migrations have advisory locking; roll out destructive migrations separately with a compatible app version.

For a demo without services: `docker run --rm -p 3206:3000 -e ADVISOR_MODE=demo budget-buddy:t6`. For Postgres, pass `DATABASE_URL` reachable from inside the container (not container localhost). Configure SMTP through T3 before promising email delivery. Production live mode requires OPENAI_API_KEY, DATABASE_URL and an HTTPS APP_URL. OPENAI_MODEL remains configurable. GET /api/health returns honest db/model flags; demo mode can be ok with db down and model missing. Readiness fails on dependency failure in live mode. Liveness uses `/api/health?probe=liveness` to avoid restarting pods on a database outage; `ok` still reports dependency status.

Two replicas share Postgres sessions, never the demo memory store. The abuse limiter is per replica. Set TRUSTED_IP_HEADER only once the ingress overwrites that header from a trusted client address and public direct pod access is blocked. Otherwise clients share the conservative unknown-IP bucket. Require an ingress-wide rate policy or Redis before increasing replica count or opening a broader beta.

Run `pnpm retention` manually or use the daily 02:15 Africa/Harare CronJob. It deletes unsaved sessions inactive for more than 30 days and emits counts only. A daily job means deletion can lag the threshold by up to a day. Alert on failed Jobs or a missed successful run for 26 hours. Saved plans are excluded even when old; cleanup and concurrent save compete atomically in Postgres. Use a DB role restricted to the needed table, and set an approved database TLS mode / CA. Kenac must define encryption, privileged audit, backup retention and restore-deletion procedures before production.
